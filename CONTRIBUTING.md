# Contributing to Subly

Thanks for your interest in contributing! Issues and pull requests are welcome.

## Ways to contribute

- **Bug reports and fixes** — especially around the x402 payer, vault flows, and mandate enforcement.
- **English translations of the design docs** — most documents under [`docs/`](docs) are currently written in Japanese; translations are highly valued.
- **New custody signer transports** — adding a provider (Turnkey, Coinbase CDP, ...) is one file implementing `RemoteSignerTransport` plus an env branch in `src/client/signer-env.ts`. See [`docs/agent-wallet-providers.md`](docs/agent-wallet-providers.md).
- **Additional payment rails** — Base / further x402 schemes (see the [roadmap](README.md#roadmap)).
- **Documentation improvements** of any kind.

## Development setup

Requirements: Node.js >= 20. Node 24 with npm 11 is recommended — the lockfile is generated by npm 11, and both CI and the Dockerfile pin Node 24.

```bash
git clone https://github.com/SublyFi/subly-payment-protocol.git
cd subly-payment-protocol
npm ci
npm run dev        # relayer on http://localhost:3000
```

With no chain configuration, the dev server boots in **detached mode** (in-memory ledger, no on-chain operations) — you can develop and test the entire API surface without keys, a database, or funds. `demo/setup-detached.sh` seeds a detached relayer with a test wallet position; it expects a throwaway key that is not in the repo, so generate one first (requires the [Solana CLI](https://docs.anza.xyz/cli/install)):

```bash
solana-keygen new --no-bip39-passphrase -o demo/env/keys/agent-detached.json
```

### Checks

Keep all of these green — CI runs exactly the same commands:

```bash
npm run typecheck     # strict TypeScript over src, tests, demo, scripts
npm test              # Vitest suites, no network or database needed
npm run build         # compiles the server to dist/

cd packages/pay
npm ci
npm run typecheck
npm run build         # esbuild bundle to dist/
```

`npm run validate:mainnet` is an optional read-only harness that simulates the full settlement path against mainnet (requires `SOLANA_RPC_URL`; moves no funds).

### Repository layout

| Path | Contents |
| --- | --- |
| `src/` | The relayer server (Fastify API, vault flows, spending mandates, Postgres ledger). |
| `packages/pay/` | The published client `@subly_fi/pay` (MCP server + CLI). Its `src/` imports shared code from the repo root; `build.mjs` inlines it at build time. |
| `demo/` | Runnable deposit/withdraw clients and legacy demos. |
| `deploy/` | Production Docker Compose stack. |
| `docs/` | Design documents ([index](docs/README.md) — defines canonical vs. legacy). |
| `tests/` | Vitest suites. |

## Pull requests

1. Fork, branch from `main`, and make your change.
2. Add or update tests for behavior changes; keep `npm test` and `npm run typecheck` green.
3. Open a PR describing **what** changed and **why**. Small, focused PRs review fastest.

A note on scope: this code moves real money on Solana mainnet. PRs that touch signing, transaction-intent validation, the yield-only guard, or mandate enforcement get extra-careful review — please explain the security reasoning in the PR description.

## Publishing

Publishing `@subly_fi/pay` to npm is maintainer-only — see [`RELEASE.md`](RELEASE.md) and [`packages/pay/PUBLISHING.md`](packages/pay/PUBLISHING.md). Do not add npm tokens or other credentials to the repository; releases use a configured trusted publisher or a maintainer's local credentials.

## Support and governance

Please check [`SUPPORT.md`](SUPPORT.md) before opening a usage request and [`GOVERNANCE.md`](GOVERNANCE.md) for project decision-making. Never disclose a vulnerability in a public issue; use [`SECURITY.md`](SECURITY.md).

## Conduct and security

- Be kind — see the [Code of Conduct](CODE_OF_CONDUCT.md).
- **Never open a public issue for a security vulnerability** — see the [Security Policy](SECURITY.md).
